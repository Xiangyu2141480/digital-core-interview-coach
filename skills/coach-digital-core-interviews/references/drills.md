# 压力追问和群面话术

把每一行当作面试官的**一个回合**。用候选人原话中的关键承诺替换泛称。对方回答得好就提高难度或接受答案；相同弱点连续出现两次，就停下来让其重答。

## 财务、技术和交付

| 客户 / 队友的追问 | 答辩要点 | 下一层可以问 |
|---|---|---|
| CFO：上线能省多少钱？今天就给数字。 | 说清已知业务量、可避免的单位成本。缺一个变量就报范围或盈亏平衡门槛。 | 给你区间下限，你还签字吗？ |
| 没裁员，所谓省钱省在哪？ | 核实加班、外包、增产或避免招聘。释放的工时单列，查是否能兑现。 | 假如排班和外包合同都不动呢？ |
| 两组方案都说提高 20%，你选谁？ | 查分母、期间、基线和同质任务，再比单位成本与错误代价。 | 容易处理的工单占比变高了呢？ |
| 准确率 95%，还有什么可犹豫的？ | 先问类别比例和高风险漏判，用混淆数据和业务容错做出上线取舍。 | 一笔错误赔付能否吃掉一天节省？ |
| 首月成功，现在全国铺开？ | 看试点样本是否含高峰和异常场景；交付、支持能力及代表性；提出下一波与停止线。 | 哪个地区先放，哪个压后？ |
| 只能给一半预算，哪块删？ | 优先保留能验证关键假设的最小流程；明确取消什么及由此放弃的收益。 | 如果这部分成本是固定承诺呢？ |
| 客户已买昂贵软件，还要留着吗？ | 已付沉没成本单列，看未来可避免费用、迁移风险和剩余合同承诺。 | 今年现金出不来，还推荐替换吗？ |
| 你根据什么断定是数据问题？ | 给可区分流程和数据问题的检验。例如同笔订单对源记录、接口和人工改动轨迹。 | 若样本显示字段完全一致呢？ |
| 技术团队说三个月，业务只等四周。 | 给四周能交付并验证的人工/规则/只读流程，标明完整自动化依赖。 | 谁在四周结束时有权停止？ |
| 一分钟停机都不行，怎么切换？ | 问关键服务的连续性目标、依赖及回退窗口；演练双跑、对账、流量切换和恢复。 | 新旧系统同时写入出现差异，谁裁定账本？ |
| 文档会过期，RAG 的回答谁负责？ | 指定内容负责人和生效版本，组织带时效问题的评测；证据不足时转人工。 | 文档互相冲突，哪种请求必须转人工？ |
| 一线说新流程每天多点三次，怎么推？ | 观察真实作业，用一线关注的时间与错误率对比；先减少重复录入再扩围。 | 推广后三周采用率下降，先找谁？ |
| 供应商演示效果很好，为何还要小试？ | 使用客户自己的代表性样本、旧流程对照、峰值、异常和失败处理，预先约定验收。 | 选不到好样本时今天怎么决定？ |
| 没数据也没预算，请现在拍板。 | 先选最可逆且符合约束的一步，说出触发更大投入的证据。 | 这一步明天谁做，多久给结果？ |
| 你坚持治理，凭什么让业务多等三个月？ | 查最少必须修的字段，给业务一个能同步试用的流程，算等待成本。 | 出现哪种数据质量情况可直接试点？ |
| 竞争对手都上 AI，我们还在质疑？ | 承认时间窗口，选一个能比较结果的切口；定义错过窗口和错误投入各损失什么。 | 如果传统规则一样快呢？ |

## 群体分歧与双语汇报

| 场景 | 可以说的一句话 |
|---|---|
| 刚开始有人报了一串框架 | “我先确认我们的交付。客户这季度只能批一个方案，我们最后要给他一个选择。我建议先把两种方案的成本放到同一个期间来看。” |
| 队友主张上 AI | “你提到售后回复慢，这个问题值得抓。我想补查一项，慢在找答案还是在等审批？前者适合知识检索，后者得先改权限流程。” |
| 两位队友一直争 | “你关心首月现金，他关心明年的扩展，两点都成立。客户把哪一个定为硬约束？如果本季现金封顶，我们可以把扩展性作为第二标准。” |
| 自己算错了 | “我更正一下，刚才把年成本按月扣了一次。按同一周期重算以后，A 的回收期会变长。我把数字改过来，再看排序是否变化。” |
| 被打断或没能抢到开场 | “我接刚才提到的回收期。这个数字还差一个采用率，我们按高低两档算一下，就能知道什么情况下值得押这笔钱。” |
| 时间不足，仍有人要加点 | “剩下时间先把交付说全。我来收口当前已有共识，保留一个还没验证的假设；负责数据的同学能补上最可能影响结论的数字吗？” |
| 面试官问谁贡献最大 | 引用真实可观察的发言和影响，清楚说出自己补了哪一项。没有看到某人的贡献就避免替其评价。 |
| 被要求立即改用英语 | “Our recommendation is to start with one site. The main uncertainty is how many hours will translate into lower spending. Finance and operations should check that together before we expand.” |
| 队友坚持错误数字 | “I agree with the operational point. Could we check the denominator? The reduction is two percentage points. Relative to the original rate, that is a quarter.” |
| 遇到不懂的专业词 | “Could I check what that term means in this case? If it refers to the maximum outage the plant can tolerate, I would use it to rule out any option that exceeds that window.” |

时间由现场规定。若有 12 分钟可讨论，练习时可用 2 分钟定任务、5 分钟分析比较、3 分钟形成建议、2 分钟演练；如只有 4 分钟就压成决定、依据、风险和交棒。有人已经组织时间时，接手一个实质工作即可。把数字读成带单位的一整句话；英语汇报先读出建议和缺口，省去冗长开场。

## 经历、动机和 AI 质疑

| 对方问 | 从真人经历取什么 | 追问方向 |
|---|---|---|
| “为什么选数字核心？” | 选一次把业务问题落实为系统改动的经历，交代是谁遇到了什么障碍、你负责什么、哪些结果可核查。连到想学的客户侧能力。 | “在客户现场碰到的阻力会和你公司内部有何不同？” |
| “你只做了执行部分，贡献在哪？” | 清楚区分自己的决定、团队执行和最终验收；说出一个你亲自定位或推动的关键节点。 | “如果去掉你的那一步，团队会多绕哪段路？依据是什么？” |
| “团队不同意你，后来证明谁对？” | 限定到一例真实分歧、证据如何修正决定。没有此案例时改讲真实的协调经历，坦白边界。 | “你自己哪一处判断变了？” |
| “你有没有交付过 ERP/云迁移？” | 没做过可说明真实经验边界，再说如何从依赖、数据核对、灰度回退迁移已有做法。 | “入场第一周先查哪一张表、找哪个人？” |
| “这张表是 AI 算的，你能自己复算吗？” | 指向题面的输入和分母，当场用同一单位重算；发现错误就更正，并说是否改变建议。 | “怎样的输入变化会翻转结论？” |
| “你的想法和 AI 有什么关系？” | 只说实际使用过的环节，再讲你采纳或舍弃的具体建议及依据。未用 AI 就说明自己的方法。 | “哪个建议看着合理但违反客户约束？” |
| “没有量化成果，凭什么相信你？” | 说明可核对的交付物、验收或前后流程。额外提出如果复做，如何取基线和对照。 | “那你明确知道的结果到底是哪一个？” |
| “总监问你为何改主意，算不算没主见？” | 指明早先判断依赖的具体条件、先前证据及后来新增证据，解释更新如何降低损失。 | “还有哪个结论在新证据下仍成立？” |

AI 快速协作的三个短请求：①“只根据这段材料，列出可能翻转选择的一条事实和它缺的数据。” ②“独立复算 A/B，列数字出处、单位、一次性费用和期间。” ③“对照题目，找出小组汇报漏掉的一项交付。” 以自己能复算、能讲清楚为准。
