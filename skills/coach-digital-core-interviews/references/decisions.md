# 从题面到可执行的客户建议

先读交付物，例如“排序三项并说明放弃哪项”“给 CIO 汇报”“提出数据需求”。一页材料有几个动词，就核对几个答案。90 分钟的面试窗口不能推出讨论时长，模拟节奏服从实际计时。

## 按问题选拆法

| 客户的问题 | 开始拆 | 能区分原因的一项证据 | 收口方式 |
|---|---|---|---|
| 利润跌，销量却涨 | 收入＝量×净价，毛利＝收入－变动成本；按产品/渠道拆销售结构，再查固定支出 | 同品同渠道单位贡献是否变，还是低毛利产品占比上升 | 解释哪一项贡献最大，下一步试点到哪个渠道 |
| 第一次进入新市场 | 可触达客户×采用率×年收入，再检验单位贡献、固定投入与供给上限 | 目标客群愿付价和已有替代方案；明确估算的地域、期间与人群 | 小范围验证需求，设停止投入的条件 |
| 客户服务慢、工厂交付迟 | 沿订单或工单逐段看等待、处理、返工；按类型分层 | 两个时间戳之间的中位数/尾部、积压量、异常集中点 | 首先动哪个环节，如何防止把排队转移至下游 |
| 预算只够一个项目 | 先过时间、预算、业务连续性等门槛，再按可兑现收益、所需能力、可逆性排序 | 一个可能翻转排名的数字，例如最低采用量 | 选一个、缓一个，说出牺牲和翻盘条件 |
| 旧系统要不要替换 | 应用依赖、业务关键性、维护成本、可停机时长、数据归属 | 恢复演练是否在业务容许时间内；对账是否通过 | 保留、接口改造、分波迁移或替换；写明切换决策人 |
| AI 试点看起来漂亮却推不开 | 从可用输入、结果质量、员工实际采用、获益兑现逐层查 | 与现有流程在同批任务对照；同时观察复核耗时和重新打开率 | 选择继续、缩小、改规则方案或停止 |
| 无数据、要估数量 | 定义口径，供给端与需求端各估一次，用容量上限校验 | 一项能最大程度缩小区间的数 | 给区间和敏感项；价格、人数、利用率不能无来源写成事实 |

## 数字核心工作中要能解释的技能

| 能力 | 被追问时应能说出来的具体动作 |
|---|---|
| 业务架构和需求澄清 | 画出用户、流程、系统和负责人。对齐一个能影响业务决定的指标，问出旧系统的使用者和依赖方。 |
| 数据工程与治理 | 说明数据从哪里来、主键能否匹配、指标按哪个时间点统计、迟到记录如何补算。指定业务口径负责人和异常处理人。 |
| 企业应用与集成 | ERP 管订单/财务等企业资源，MES 记录车间执行，CRM 管客户交互，WMS 管仓储作业。说清哪个系统对哪个字段负责，接口失败后如何对账。 |
| 云与应用现代化 | 从工作负载和业务连续性选保留、改造或迁移；计入双跑、人员、许可和退出成本；约定恢复时间与可接受数据损失，演练回退。 |
| BI、规则、RAG 和 Agent | 报表用于看清发生了什么；确定性规则处理清晰且稳定的判断；带来源的检索生成适合文档知识问答；多步工具调用需要权限、可追溯动作与人工审批。比较每个额外环节的收益和成本。 |
| AI 效果评估 | 准备代表性任务与困难反例，分开检查来源正确、答案正确、漏答、时延、单任务成本、人工复核。区分试验样本和线上真实分布。 |
| 财务与价值验证 | 解释边际贡献、现金节省、产能释放、全生命周期成本、回收期和敏感性；为客户设置一项能验证的获益口径。 |
| 交付与变革 | 选一个业务负责人和一位一线代表，用相似班组或上线前后可比窗口做试点；监测另一个环节有无恶化。选一种培训和反馈方式。 |
| 双语表达与协作 | 30 秒内能接住一个异议，把指标、取舍和下一步交给下一位同学。英文能读图、复述单位、正式更正一个数字。 |

## 算账时先写口径

- 可兑现年收益＝年业务量×在假设下可改善的比例×单位边际价值，再考虑实际采用或兑现比例。若比例已按全部业务量测得，不能再次乘覆盖率。若是纯工时收益，注明能否减少加班、外包或增加有效产出。
- 年净收益＝可兑现年收益－新增年运营成本。简单回收期＝一次性投资÷稳态月净现金流；假设均匀流入且已投产。存在实施期、爬坡或负净流入，按月累计现金流，必要时说明无法回收。
- 同周期 ROI＝（该期增量现金收益－该期全部增量成本）÷该期全部增量成本。TCO 比较同一个周期和工作量的部署、实施、运行、人员、迁移、双跑、退出费用；收益和成本逐项避免重复。
- 数字检验：从 8% 到 6% 是下降 2 个百分点，相对下降 25%。平均时长变短可能伴随复杂工单尾部恶化，要求同组样本和分层口径。
- 遇到对方报价“准确率 95%”，问分母、任务比例、错误代价及对照。若 98% 的工单本来无需升级，全部预测“不升级”也有 98% 准确率；优先看高风险漏判与节省的净处理时长。

## 一条完整的发言怎样形成

原创例：零售商为降低缺货准备买预测模型。店长说系统显示有货，货架却是空的。决策是先修库存记录还是买预测。抽一批缺货 SKU，比较系统库存、实盘和到货时间。若账面和实际偏差集中在调拨环节，先改扫描与同步；若账实一致且促销周偏差集中，再试预测。用缺货时长和报废率共同验收。遇到“今天必须选”就按当前证据选择盘点与接口小试点，并明确哪条抽查结果会让你改主意。
